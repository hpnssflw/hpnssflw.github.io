Five plans this year ran the same way: an AI subagent implemented each task, a fresh AI reviewer checked it against that brief, then a separate AI review read the whole diff at once. That last pass is where the real findings showed up.

## What to watch for

- A claim contradicted by data another task wrote: the status widget said "nothing published, nothing public" while a different task had already pushed the full curated queue public. The first fix still under-claimed it, naming only one of the two exposed files.
- A leak split across files: the bot token reached the run log because one file's exception text embedded it and another logged that text. Neither file's own review saw the other half.
- Not everything crosses a boundary: a missing pacing/429 handler in the same plan lived in one file — a task review could've caught that.

## Why it's interesting

- The final pass forced code fixes in three of five plans, found no code defects in a fourth (one product call instead), and only doc fixes in the fifth.
- It's cheap — one extra review — but not always one pass: one plan took two fix rounds.
