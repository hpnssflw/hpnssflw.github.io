I ran five plans this year the same way: an AI subagent implemented each task, a fresh AI reviewer checked it against that task's brief, then one more AI review read the whole diff at once — the only pass that catches boundary-crossing problems.

## What to watch for

- A claim contradicted by data another task wrote: the agent's plan page said "nothing published, nothing public" — already false once an earlier task's workflow made the queue public, uncaught by a later narrative edit. My first reword still missed it; a second round said so plainly.
- A leak split across files: exception text that could embed the bot token fed a log line written a month earlier, before Telegram or any real token existed. Each half looked fine alone.
- Not everything crosses a boundary: a missing pacing/429 handler lived in one file — a task review could've caught it.

## Why it's interesting

- The final pass forced code fixes in three of five plans, found none in a fourth, and only doc fixes in the fifth.
- It's cheap — one extra review — but not always one pass: one plan took two rounds.

## In practice
